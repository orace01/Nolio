# Nolio back end

How the AI engine is organized, and how to turn it on.

## Who does what

Gemini runs every AI step. The calls go through `src/server/ai/gemini.ts`, which asks for JSON matching a schema and tries the next model of a list when one is overloaded or out of quota.

| Step of the flow | Gemini models | Code |
|---|---|---|
| 1. Analysis of the idea | quick (`GEMINI_MODELS`) | `src/server/ai/analysis.ts`, `POST /api/ai/analyze` |
| 2. Details: profiles, length | quick | same; video titles come from the platforms (oEmbed), `POST /api/media/inspect` |
| 3. Design: ready-made styles | none, chosen by the user | `src/lib/app/catalog.ts` |
| 3. Design: "Create my style" (Pro) | quick | `src/server/ai/design.ts`, `POST /api/ai/design` |
| 3. Images generated by AI (Pro) | images (`GEMINI_IMAGE_MODELS`) | `POST /api/ai/images` |
| 4. Outline | writer (`GEMINI_WRITER_MODELS`) | `src/server/ai/writer.ts`, `POST /api/ai/outline` |
| 5 to 8. Writing, layout fit, videos and links, final check | writer, in the worker | `src/server/engine/create.ts` |
| 9. Comments | writer, in the worker | `src/server/engine/fixes.ts` |
| 10. PDF, print PDF, EPUB, cover image | none: Chrome and code, in the worker | `src/server/engine/export.ts` |

Every answer of the flow is saved to the server as it is given (`PUT /api/draft`): the dossier of the ebook grows step by step, and each AI call receives the whole dossier (`src/server/ai/dossier.ts`).

When the user approves the outline, `POST /api/ebooks` puts a job in the queue. The worker (`npm run worker`) takes it, writes the ebook, makes the files, and reports its progress to the "Creating" screen.

Without a key, each service keeps its demo behavior (`src/lib/app/content.ts`), so the app always works. If a provider fails (no credit, overloaded), the screen falls back to the stand-in instead of blocking the user.

## Turning it on

1. **Supabase**: create a project on supabase.com, then fill `.env.local` (see `.env.example`):
   - `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: Project settings > API keys.
   - `SUPABASE_SECRET_KEY`: same page, secret key.
   - `SUPABASE_DB_URL`: Project settings > Database > Connection string. Use the **Session pooler** variant (`...pooler.supabase.com:5432`), not the direct connection (`db.<ref>.supabase.co:5432`) - the direct one is IPv6-only, which many hosts and sandboxes cannot reach.
2. Create the tables, the queue and the storage: `npm run db:setup`.
3. In Supabase > Authentication > URL configuration:
   - Site URL: the address of the app, for example `http://localhost:3000`.
   - Redirect URLs: add `http://localhost:3000/api/auth/callback` (and the production address later).
4. Key: `GEMINI_API_KEY`, from Google AI Studio. On the free tier only the Flash models answer; enable billing on the key for the Pro model (better writing) and for generated images.
5. Start the app and the worker, in two terminals:

   ```
   npm run dev
   npm run worker
   ```

6. After changing `.env.local`, restart both. For a production build, rebuild (`npm run build`).

Chrome is needed by the worker for the PDFs. It is found automatically on usual paths; otherwise set `CHROME_PATH`.

Node 20 has no global `WebSocket`, which `@supabase/supabase-js` needs at client-construction time even though Nolio never uses Realtime. `src/server/supabase.ts` passes the `ws` package as the transport to work around this; nothing to configure, just don't remove that import when touching the file.

## Useful to know

- Models can be changed without touching the code: `GEMINI_MODELS`, `GEMINI_WRITER_MODELS`, `GEMINI_IMAGE_MODELS` (lists, tried in order).
- Until Stripe is connected, the plan buttons switch plans directly. Set `NOLIO_ALLOW_PLAN_SWITCH=false` to block it before going live.
- "Your ebook is ready" emails are sent only if `RESEND_API_KEY` is set.
- A creation that fails is retried twice, a minute apart. After that, the ebook shows "Not finished" with a button to start again.
